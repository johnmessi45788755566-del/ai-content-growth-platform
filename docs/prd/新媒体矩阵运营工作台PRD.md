# 新媒体矩阵运营工作台 PRD 草案

## 1. 产品定位

新媒体矩阵运营工作台是面向企业多平台账号运营的后台系统，核心解决多账号管理、内容自动生成、定时任务执行、数据反馈分析和 AI 自动优化的问题。

产品不按单一运营流程组织，而是按业务对象组织，核心模块包括：

- 账号矩阵
- 数据分析
- 内容创作
- 任务中心
- 系统设置

V1 阶段支持微信公众号、小红书、抖音进入账号矩阵，视频号作为后续预留。账号登录统一采用本地独立 Chrome 打开平台真实管理后台，由用户使用对应平台 App 扫码并保存独立登录态。微信公众号发布直接复用账号矩阵中已扫码保存的独立浏览器登录态，不要求用户另行填写 AppID、AppSecret、账号或密码；小红书图文笔记复用账号矩阵中的小红书登录态，通过浏览器自动化把本地图片文件交给小红书页面上传控件，并按发布方式分别点击“发布”或“暂存离开”。抖音在 V1 只实现真实登录和数据同步，不开放发布。浏览器自动化需要在产品中标注稳定性、风控和人工接管边界。

## 2. 背景与问题

当前新媒体运营中存在以下问题：

- 多账号管理分散，账号定位、运营人、平台授权和账号状态难以统一维护。
- 内容创作依赖人工，选题、写稿、排版、发布流程重复，效率较低。
- 数据反馈分散，难以按账号和作品持续复盘内容效果。
- AI 生成内容缺少账号记忆，无法长期结合账号定位和历史表现持续优化。
- 定时任务和多任务并行能力不足，难以支撑矩阵化运营。

因此，需要建设一个以账号矩阵为基础，以数据反馈为驱动，以 AI 内容生成和自动任务为核心能力的新媒体运营工作台。

## 3. 核心目标

- 提高运营效率：减少人工选题、写稿、发布、复盘的重复操作。
- 支持矩阵管理：统一管理多个平台、多个账号。
- 实现自动化发布闭环：支持即时生成内容和定时任务自动生成内容。微信公众号和小红书图文均提供“同步到平台草稿箱”和“一键发布”两个独立动作；两个动作只共用内容生成、图片上传和正文填写步骤，最终提交按钮分开执行；所有平台均不做失败后自动切换动作，只有取得平台侧与本次操作绑定的成功凭据，才记录为“已生成平台草稿”或“已发布”。
- 建立数据闭环：基于账号和作品数据反馈，自动调整后续内容策略。
- 沉淀账号记忆：每个账号形成独立定位、用户画像、风格偏好和 AI 动态规则。

### 4.1 竞品分析结论

现有竞品大致分为三类：

1. 账号矩阵类：以新榜矩阵通为代表，强在多账号管理、授权状态、数据总览和账号筛选。
2. 内容创作类：以壹伴为代表，强在公众号图文编辑、AI 写作和排版辅助。


本项目的差异化方向是：以账号矩阵作为基础对象，以内容创作作为效率工具，以任务中心实现自动化执行，以数据分析驱动 AI 自动调整账号内容规则，从“工具辅助运营”升级为“AI 驱动的矩阵运营工作台”。

## 7. 核心模块

### 7.1 账号矩阵

账号矩阵用于统一管理各平台账号，是“账号管理 + AI 账号档案”的基础模块。

账号矩阵需要同时支撑三类后续能力：

- 内容创作：生成内容时读取账号定位、面向用户、内容风格和禁忌方向。
- 任务执行：创建自动任务时选择平台账号，并绑定账号授权状态。
- 数据反馈：AI 根据账号和作品数据更新账号动态偏好。

账号矩阵采用“列表页 + 独立详情页”结构。列表页用于账号管理、筛选和批量操作；独立详情页用于维护单个账号的基础信息、授权状态和 AI 档案。

#### 7.1.1 页面参考

账号矩阵页面可参考新榜矩阵通的后台结构：

- 左侧为一级导航和模块内二级菜单。
- 模块内展示账号管理状态总览。
- 主区域以表格形式展示账号列表。
- 支持平台、团队、运营人、授权情况、账号标签等筛选。

#### 7.1.2 列表页结构

账号矩阵列表页包含：

| 区域 | 内容 |
| --- | --- |
| 管理状态总览 | 已添加账号数、已授权账号数、在线账号数、离线账号数、监测中账号数、授权失效账号数 |
| 平台分布 | 按公众号、视频号、小红书等平台展示账号数量 |
| 筛选区 | 平台、团队、运营人、授权状态、登录状态、监测状态、账号标签 |
| 操作区 | 添加账号、批量授权、授权检测、更新账号信息、自定义字段 |
| 账号表格 | 展示账号名称、平台、标签、运营人、授权状态、登录状态、监测状态、添加时间、操作 |

账号矩阵列表页只展示账号管理状态，不展示粉丝数、播放量、点赞数等运营效果数据。运营效果数据统一进入数据分析模块。

#### 7.1.3 添加账号与数据同步流程

- 用户点击添加账号，V1 可选择微信公众号、小红书或抖音；视频号作为后续预留。
- 选择平台后，系统在本机自动打开独立 Chrome 窗口，并进入该平台真实的官方登录或管理后台页面；工作台本身不生成模拟二维码。
- 用户在平台真实页面使用对应平台 App 扫码并完成平台确认。
- 系统持续检测真实登录结果，只有确认登录成功后才创建账号记录，并为该账号保存独立浏览器登录态；账号名称和平台账号 ID 优先从平台登录页及登录会话中真实读取。
- 登录成功后关闭登录窗口，账号进入账号矩阵；登录超时、用户关闭窗口或扫码失败时不创建账号。账号标签和运营人属于工作台内部管理字段，平台不会返回；默认分别显示“未设置”和“未分配”，由用户在账号编辑入口维护。
- 后续数据同步、定时发布和人工接管复用该账号独立登录态，不共享不同账号的 Cookie。
- 账号登录态失效时，账号不能用于定时任务发布，需要重新打开平台真实登录页扫码。
- 微信公众号 V1 的同步草稿和直接发布均复用该账号的真实网页登录态；账号失效时必须重新扫码。产品侧不要求用户填写 AppID、AppSecret、平台账号或密码。

#### 7.1.4 登录状态与重新扫码流程

账号矩阵需要把“授权状态”和“登录状态”分开展示和处理：

| 状态类型 | 字段含义 | 示例 |
| --- | --- | --- |
| 授权状态 | 账号是否已经添加到工作台并保存过平台登录态 | 未授权、已授权、授权失效 |
| 登录状态 | 当前保存的浏览器登录态是否仍可进入平台后台 | 在线、离线、检测中、未知 |
| 同步状态 | 最近一次账号信息或数据同步结果 | 已同步、同步中、同步失败 |

账号列表和账号详情均需要展示登录状态：

- 在线：绿色圆点 + 在线。表示当前登录态可用，可用于数据同步和发布任务。
- 离线：红色圆点 + 离线。表示平台登录态失效，需要重新扫码。
- 检测中：灰色或蓝色圆点 + 检测中。表示系统正在检测真实平台登录态。
- 未知：灰色圆点 + 未知。表示尚未完成检测或检测结果不可用。

账号点击规则：

- 在线账号：点击账号进入账号详情，支持更新账号信息、同步数据和查看账号档案。
- 离线账号：点击账号直接打开该平台扫码登录弹窗，不进入发布或同步流程。
- 未知账号：点击账号后先触发一次登录态检测；检测成功后显示在线并进入详情，检测失败后显示离线并打开扫码登录弹窗。
- 检测中账号：点击时不重复打开弹窗，只展示“正在检测登录状态”。

重新扫码登录流程：

```mermaid
flowchart TD
    A["账号矩阵点击离线账号"] --> B["打开平台真实扫码登录弹窗"]
    B --> C["用户在平台页面扫码并确认登录"]
    C --> D{"系统检测登录是否成功"}
    D -->|成功| E["立即关闭登录弹窗"]
    E --> F["更新登录状态为在线"]
    F --> G["清空同步失败原因"]
    G --> H["触发账号信息同步"]
    D -->|失败或超时| I["保持登录状态为离线"]
    I --> J["展示失败原因和重新扫码入口"]
```

账号级浏览器互斥规则：

- 同一平台账号同一时间只允许一个浏览器任务使用该账号 Profile。
- 浏览器任务包括扫码登录、登录态检测、账号信息同步、数据同步和发布任务。
- 如果同一账号已有浏览器任务运行，新的操作需要进入等待或直接提示“该账号正在执行登录 / 同步 / 发布，请稍后再试”。
- 登录态失效属于不可自动恢复错误，发布任务不应继续重试打开同一账号 Profile，避免触发浏览器 Profile 锁。

### 7.3 内容创作

内容创作是运营人员主动进行公众号图文创作的板块，用于通过 AI 辅助完成标题确认、文章生成、图片生成和文章排版。发布时选择一个已授权微信公众号账号，并明确选择“同步到平台草稿箱”或“一键发布”。

V1 阶段先支持图文生成，后续预留视频生成工具接入。内容创作页面调用底层图文生成能力，根据用户输入的主题生成图文内容。

内容创作页本身不负责账号档案读取。账号档案在发布阶段选择账号后读取，用于匹配发布账号、记录作品归属，并为后续数据反馈和 AI 规则更新提供关联关系。

定时任务中的自动生成不属于内容创作页面流程，由任务中心到点后自动触发同一套图文生成能力。

#### 7.3.1 页面结构

内容创作模块包含：

| 步骤 | 说明 |
| --- | --- |
| 标题确认 | 通过和 AI 对话输入想写的主题、目标客户、产品卖点和转化目标，AI 生成选题方向和标题 |
| 生成文章 | 基于已确认标题生成公众号文章内容，并按段落展示和编辑 |
| 生成图片 | 基于标题和文章内容生成封面图和正文配图，支持重新生成和选择图片 |
| 文章排版 | 组合标题、文章内容、封面图和正文配图，支持编辑排版、预览和直接发布 |
| 草稿箱 | 自动保存内容创作中每一步的结果，支持从对应步骤恢复继续创作 |
| 发布配置区 | 文章排版页选择一个已授权微信公众号账号，并提供“同步到平台草稿箱”和“一键发布”两个独立按钮 |
| 发布结果区 | 展示发布状态、平台返回结果和失败原因 |

#### 7.3.2 创作流程

1. 用户在“标题确认”中和 AI 对话，输入想写的内容、目标客户、产品卖点和转化目标。
2. AI 生成选题方向和标题，用户确认标题。
3. 用户进入“生成文章”，系统基于已确认标题生成公众号文章内容。
4. 用户按段落编辑文章内容，系统实时保存到草稿箱。
5. 用户进入“生成图片”，系统基于标题和文章内容生成公众号封面图和正文配图。
6. 用户选择要使用的封面图和正文配图，可重新生成图片。
7. 用户进入“文章排版”，系统组合标题、正文、封面图和配图生成排版预览。
8. 用户编辑排版并选择一个已授权微信公众号账号。
9. 用户点击“同步到平台草稿箱”或“一键发布”，两个动作互不自动切换。
10. 系统读取所选账号档案和已保存的浏览器登录态，执行所选动作。
11. 平台要求运营人员扫码确认时，操作进入“待人工确认”，确认后从原发布作业继续。
12. 只有取得平台侧本次操作的成功凭据后，系统才生成对应的作品记录和发布记录。

#### 7.3.3 输入信息

| 字段 | 说明 |
| --- | --- |
| 想写的内容 | 用户通过对话描述本次想写的主题或方向 |
| 目标客户 | 本次内容面向的人群，例如小微企业老板、个体户、财务人员 |
| 产品卖点 | 本次内容需要体现的产品能力或服务价值 |
| 转化目标 | 本次内容希望达成的目标，例如咨询、试用、加群、领取资料 |
| 已确认标题 | 用户最终确认用于生成文章的标题 |

#### 7.3.4 发布信息

| 字段 | 说明 |
| --- | --- |
| 平台 | V1 支持微信公众号和小红书图文 |
| 账号 | 从账号矩阵中选择一个与平台匹配的已授权且登录状态在线账号，不支持一篇内容同时发布到多个账号或平台 |
| 发布动作 | 同步到平台草稿箱、一键发布；必须由用户明确选择，不自动降级或切换 |
| 账号档案 | 选择账号后读取，用于记录作品归属和后续数据反馈 |

#### 7.3.5 输出内容

| 字段 | 说明 |
| --- | --- |
| 所属账号 | 当前内容对应的发布账号 |
| 选题方向 | AI 根据用户对话生成的内容方向 |
| 标题 | 用户确认后的标题 |
| 正文段落 | AI 基于标题生成的公众号文章正文 |
| 封面图 | AI 基于标题和文章内容生成的公众号封面图 |
| 正文配图 | AI 基于文章内容生成的正文配图 |
| 排版预览 | 标题、正文、封面图和正文配图组合后的公众号文章预览 |
| 发布状态 | 未发布、发布中、待人工确认、已生成平台草稿、已发布、发布失败 |

#### 7.3.6 发布规则

- 内容创作阶段包含标题确认、生成文章、生成图片和文章排版四个步骤。
- 每个步骤完成后，系统都需要自动保存到草稿箱。
- 草稿箱需要记录当前完成步骤，并支持用户从对应步骤继续创作。
- 页面内步骤条只展示四个步骤，不展示发布。
- 发布是文章排版完成后的页面操作。
- 用户在文章排版页选择一个已授权微信公众号账号后，再点击“同步到平台草稿箱”或“一键发布”。
- 一个内容项目只能绑定一个平台账号；V1 不支持同一篇文章多平台或多账号同时发布。
- “同步到平台草稿箱”和“一键发布”是两个独立动作，任一动作失败时都不自动执行另一个动作。
- 平台要求扫码确认时保留原发布作业并进入待人工确认，运营人员完成确认后继续原作业。
- 只有平台返回与本次动作绑定的成功凭据后，系统才创建作品记录和发布记录；本地待发布包不能作为成功依据。
- 发布失败时，需要展示失败原因，并允许从发布记录或任务详情中重试。
- V1 不设置强制审核流，是否增加人工确认作为后续待确认项。

#### 7.3.7 草稿箱联动

草稿箱用于保存人工内容创作过程中的中间结果。用户完成任一步骤后，系统都需要生成或更新草稿记录。

草稿箱列表建议展示：

| 字段 | 说明 |
| --- | --- |
| 草稿标题 | 当前已确认标题，未确认标题时展示用户输入的主题摘要 |
| 当前步骤 | 标题确认、生成文章、生成图片、文章排版 |
| 内容类型 | V1 默认为公众号图文 |
| 更新时间 | 草稿最近一次自动保存时间 |
| 运营人 | 当前草稿创建或编辑人 |
| 操作 | 继续创作、删除草稿 |

#### 7.3.8 边界说明

主题只是内容创作的输入参数，不作为任务中心的一级管理对象。

内容创作模块偏人工主动操作；任务中心偏自动化调度执行。两者共用底层图文生成能力，但入口和执行流程不同。

任务中心到点自动生成图文并发布时，不需要用户进入内容创作页面完成生成。

V1 仅支持图文生成，不做视频自动生成。后续接入视频生成工具时，可在内容类型中扩展短视频脚本、分镜、素材生成等能力。

### 7.4 任务中心

任务中心用于管理自动化任务，不按主题分组。任务中心关注“哪个平台、哪个账号、什么时间、执行什么动作、执行结果如何”。

任务中心是定时自动化入口。用户可以新增任务，也可以编辑已有任务。新增任务时，需要选择已授权且登录状态在线账号、填写主题约束、填写创作要求、选择任务类型和执行方式。主题只是选题约束，不作为最终标题；任务到点后，系统会结合账号信息、主题约束和创作要求，在内容创作的“标题确认”能力中生成标题建议，并由 AI 自动选择合适标题继续生成文章、图片和排版。

V1 任务中心真实执行微信公众号图文任务和小红书图文任务，且任务必须绑定账号矩阵中对应平台的一个已授权且登录状态在线的账号。任务发布方式保留“一键发布”和“同步到平台草稿箱”两个选项；两个动作互不自动切换。小红书图文任务在生成图片和正文后，共用上传图片、填写标题和正文步骤；选择“一键发布”时点击小红书页面的“发布”，选择“同步到平台草稿箱”时点击“暂存离开”。抖音在 V1 仅支持账号登录和数据同步，不进入发布任务；视频号为后续预留。

任务的核心定义是：

> 任务 = 平台 + 单个已授权账号 + 执行时间 + 发布动作

任务中心支持多任务并行执行。同一个主题如果要发多个账号，可以创建多条任务，但任务中心仍按任务条目平铺展示，不做“主题任务 -> 子任务”的层级结构。

#### 7.4.1 页面结构

任务中心包含：

| 页面 / 区域 | 说明 |
| --- | --- |
| 任务列表 | 按平台、账号、时间、状态查看任务，并支持查看详情、编辑和删除 |
| 新增任务 | 选择已授权且登录状态在线账号，配置主题约束、创作要求、任务类型和执行方式 |
| 编辑任务 | 修改已有任务的账号、主题约束、创作要求、任务类型、执行方式和执行时间，未修改项沿用原配置 |
| 任务详情 | 查看任务配置、生成内容、发布结果、失败原因和重试记录 |
| 状态筛选 | 按待执行、执行中、待人工确认、已发布、已生成平台草稿、失败、已重试筛选 |
| 批量重试 | 对失败任务进行多选，并立即重新执行选中的失败任务 |

#### 7.4.2 任务列表字段

| 字段 | 说明 |
| --- | --- |
| 平台 | V1 支持微信公众号和小红书图文；抖音仅登录和数据同步，视频号预留 |
| 账号 | 执行任务的账号 |
| 执行时间 | 任务计划执行时间 |
| 任务类型 | V1 为微信公众号图文生成或小红书图文生成 |
| 选定标题 | 任务执行时由 AI 基于主题、账号信息和创作要求自动生成并选择 |
| 任务状态 | 待执行、执行中、待人工确认、已发布、已生成平台草稿、失败、已重试 |
| 关联内容 | 任务生成的内容项目、草稿和待发布包 |
| 失败原因 | 任务失败时展示 |
| 重试记录 | 展示任务重试次数和结果 |

#### 7.4.3 新增 / 编辑任务字段

| 字段 | 说明 |
| --- | --- |
| 平台 | 新增任务时配置；编辑任务时可修改，不修改则沿用原配置 |
| 账号 | 新增任务时配置；编辑任务时可修改，不修改则沿用原配置；账号必须已授权且登录状态在线 |
| 主题 | 新增任务时配置；编辑任务时可修改，不修改则沿用原配置。主题只是选题约束，不直接作为最终文章标题 |
| 创作要求 | 非必填，用于补充文章中想加入的例子、客户群体、表达要求等 |
| 选定标题 | 任务执行时由 AI 自动生成并选择，不在新建任务时人工选择 |
| 任务类型 | V1 支持微信公众号图文生成和小红书图文生成；其他平台仅保留后续扩展位置 |
| 执行方式 | 单次执行、重复执行 |
| 执行时间 | 位于执行方式配置之后；单次执行选择日期和时间 |
| 重复规则 | 选择重复执行后展示；支持每天、每周。每天只需选择执行时间；每周需要选择周几和执行时间 |
| 发布动作 | 一键发布、同步到平台草稿箱；默认一键发布，失败时不自动切换到另一个动作 |

#### 7.4.4 任务类型

V1 任务类型：

- 微信公众号图文生成并发布：复用账号矩阵中该账号已保存的真实浏览器登录态执行
- 小红书图文生成并发布：复用账号矩阵中该账号已保存的真实浏览器登录态执行，按发布方式点击“发布”或“暂存离开”

后续可扩展：

- 视频创作
- 同步数据
- 生成数据报告

#### 7.4.5 定时规则

V1 支持：

- 单次任务
- 重复任务：每天、每周
- 多任务并行执行

暂不做复杂的自动排期算法。

重复任务无结束时间，用户可通过删除任务停止后续执行。

任务到点后由系统自动执行，不进入内容创作页面；生成内容、待发布包、发布结果、平台草稿结果和失败原因在任务详情中查看。

任务发布前登录态拦截规则：

- 任务开始发布前必须读取账号矩阵中的授权状态和登录状态。
- 授权状态不是已授权时，任务不进入发布阶段，失败原因为“账号未授权，请先添加或重新授权账号”。
- 登录状态为离线时，任务不启动浏览器发布页，失败原因为“账号离线，请重新扫码登录”。
- 登录状态为未知时，系统先执行一次快速登录态检测；检测成功后继续发布，检测失败后把账号标记为离线并终止发布。
- 登录状态为检测中时，任务等待账号检测完成；超过等待时间仍未确认在线，则终止发布并提示稍后重试。
- 小红书登录态失效属于不可自动恢复错误，不进行发布重试；需要用户在账号矩阵重新扫码登录后再手动重试任务。
- 同一账号同一时间只能有一个发布、登录或同步浏览器任务运行，避免多个 Chromium 实例抢占同一个浏览器 Profile。

#### 7.4.6 任务状态

| 状态 | 说明 |
| --- | --- |
| 待执行 | 任务已创建，尚未到执行时间 |
| 执行中 | 系统正在生成内容或发布内容 |
| 待人工确认 | 平台要求运营人员扫码确认；确认完成后继续原发布作业 |
| 已发布 | 内容生成并成功发布到对应平台账号 |
| 已生成平台草稿 | 内容生成并成功进入对应平台草稿箱，等待人工确认发布 |
| 失败 | 内容生成或发布失败 |
| 已重试 | 失败任务已触发过重试 |

#### 7.4.7 任务详情

点击任务条目后，进入任务详情。

任务详情包含：

- 平台
- 账号
- 执行时间
- 任务类型
- 任务状态
- 创作主题
- 账号定位
- 面向用户
- 内容风格
- 生成内容
- 发布结果、平台草稿状态和待发布包
- 失败原因
- 重试记录

#### 7.4.8 失败处理

- 任务失败时需要记录失败阶段：生成失败、发布失败、接口失败、授权失效等。
- 任务失败时需要展示失败原因。
- 任务失败后支持人工重试；批量重试时可以多选失败任务并立即重新执行。
- 如果账号授权失效，应提示用户先处理账号授权。
- 多任务并行时，单个任务失败不影响其他任务继续执行。

### 7.5 首页

首页用于展示整体运营概览和常用入口，帮助用户快速了解当前账号矩阵、任务和数据状态。

首页建议包含：

| 区块 | 内容 |
| --- | --- |
| 账号概览 | 已添加账号数、已授权账号数、在线账号数、离线账号数、授权失效账号数 |
| 今日任务 | 今日待执行、执行中、成功、失败任务数量 |
| 内容概览 | 今日生成内容数、今日发布内容数、发布失败数 |
| 数据摘要 | 关键账号或作品的数据变化摘要 |
| 快捷入口 | 添加账号、创建内容、创建定时任务、查看数据分析 |

首页只做概览和入口，不承载完整的数据分析和账号管理能力。

### 7.6 系统设置

系统设置用于维护平台接入、成员和基础配置，不承载日常运营流程。日常账号管理、数据查看、内容创作和任务执行仍分别在账号矩阵、数据分析、内容创作和任务中心中完成。

V1 建议包含：

| 配置项 | 说明 |
| --- | --- |
| 平台授权配置 | 管理公众号等平台接入配置 |
| 团队成员 | 管理系统成员和所属团队 |
| 运营人配置 | 用于账号负责人筛选和任务归属 |
| AI 配置 | 管理 AI 生成能力的基础配置 |
| 发布安全配置 | 管理发布前确认、失败提醒等安全策略 |

#### 7.6.1 平台授权配置

平台授权配置用于维护平台接入状态和授权入口。

| 字段 | 说明 |
| --- | --- |
| 平台 | 公众号、视频号、小红书等 |
| 授权状态 | 未授权、已授权、授权失效 |
| 授权账号数 | 当前平台已接入账号数量 |
| 最近检测时间 | 最近一次授权状态检测时间 |
| 操作 | 去授权、检测授权、查看接入说明 |

V1 不在 PRD 中细化 AppID、密钥、回调地址等技术参数，仅描述产品侧配置能力。

#### 7.6.2 团队成员

团队成员用于维护系统使用人员，支撑账号负责人、任务归属和基础协作。

| 字段 | 说明 |
| --- | --- |
| 成员姓名 | 系统成员名称 |
| 手机号 / 邮箱 | 成员联系方式 |
| 所属团队 | 成员所属团队 |
| 状态 | 启用、停用 |
| 操作 | 新增、编辑、停用 |

V1 只做基础成员管理，不细化复杂角色权限、菜单权限和数据权限。

#### 7.6.3 运营人配置

运营人配置用于维护可分配到账号和任务上的运营人员。

| 字段 | 说明 |
| --- | --- |
| 运营人 | 可被选择为账号负责人或任务负责人 |
| 所属团队 | 运营人所属团队 |
| 负责账号数 | 当前绑定的账号数量 |
| 状态 | 启用、停用 |
| 操作 | 新增、编辑、停用 |

运营人配置需要和账号矩阵中的运营人筛选、任务中心中的任务归属保持一致。

#### 7.6.4 AI 配置

AI 配置用于维护内容生成和规则自动更新的基础策略。

| 字段 | 说明 |
| --- | --- |
| 默认生成模型 | 内容创作和定时任务默认使用的生成模型 |
| 生成风格默认值 | 默认写作风格，例如专业、科普、案例化等 |
| 敏感词 / 禁忌方向 | 生成内容时需要规避的词和方向 |
| 规则自动生效开关 | 控制 AI 根据数据反馈改写账号规则后是否自动生效 |
| 回滚记录入口 | 查看 AI 规则变更记录，并支持回滚 |

V1 不做多模型复杂路由，只提供默认模型和基础生成策略配置。

#### 7.6.5 发布安全配置

发布安全配置用于控制自动发布过程中的基础风险提示。

| 字段 | 说明 |
| --- | --- |
| 发布前确认 | 控制立即发布或定时发布前是否需要人工确认 |
| 失败提醒 | 任务生成或发布失败时提醒相关运营人 |
| 重试提醒 | 失败任务触发重试或重试失败时提醒相关运营人 |
| 授权失效提醒 | 平台账号授权失效时提醒相关运营人或管理员 |
| 提醒方式 | 站内通知、消息中心等基础提醒方式 |

V1 默认不设置强制审核流。发布前确认作为可配置项保留，是否开启由系统配置决定。

#### 7.6.6 边界说明

- 系统设置只提供基础配置能力，不承载日常运营流程。
- V1 不细化复杂权限体系。
- V1 不细化平台接口技术参数。
- 平台授权、AI 配置和发布安全配置需要服务于账号矩阵、内容创作和任务中心。

## 8. AI 数据反馈闭环

AI 不只是生成内容，还要基于数据反馈调整账号规则。AI 数据反馈闭环是连接“数据分析、账号档案、内容创作、任务中心”的核心机制。

### 8.1 闭环流程

1. 内容发布。
2. 平台数据回流。
3. 系统按账号和作品分析表现。
4. AI 判断哪些内容方向、标题结构、表达风格、发布时间效果更好。
5. AI 自动更新账号动态偏好。
6. 后续内容生成自动应用新规则。

### 8.2 规则变更方式

AI 规则更新采用：

- 自动生效
- 保留变更记录
- 支持回滚

规则自动生效后，需要在账号详情页和数据分析模块中都能查看变更记录。

### 8.3 AI 规则版本字段

| 字段 | 说明 |
| --- | --- |
| 账号 | 规则所属账号 |
| 规则类型 | 标题、内容方向、表达风格、发布时间等 |
| 变更前内容 | 原规则内容 |
| 变更后内容 | 新规则内容 |
| 数据依据 | 触发变更的数据表现 |
| 生效时间 | 规则生效时间 |
| 操作 | 查看详情、回滚 |

### 8.4 可调整规则范围

V1 可调整的规则范围包括：

| 规则类型 | 说明 |
| --- | --- |
| 标题偏好 | 根据推荐数、阅读量 / 播放量、点赞等数据调整标题结构 |
| 内容角度 | 根据高表现作品提炼更适合账号的内容切入点 |
| 表达风格 | 根据互动表现调整专业、口语化、案例化等表达倾向 |
| 发布时间 | 根据内容表现调整后续建议发布时间 |
| 禁忌方向 | 根据低表现内容弱化不适合继续创作的方向 |

### 8.5 回滚规则

- 每次 AI 规则更新都需要生成规则版本记录。
- 用户可以查看调整前、调整后和数据依据。
- 用户可以回滚到上一版本规则。
- 回滚后，后续内容生成应使用回滚后的规则。
- 回滚行为也需要记录到规则变更记录中。

### 9.1 V1 重点做

- 公众号账号矩阵管理
- 账号档案维护
- 首页运营概览
- 图文内容生成
- 内容创作草稿箱

## 10. 验收场景

- 用户能在账号矩阵中添加多个平台账号，并通过平台、标签、运营人筛选。
- 用户能进入账号详情维护定位、目标用户、内容风格和禁忌方向。
- 数据分析默认展示账号维度数据，并可切换到作品维度。
- 用户能在内容创作页通过标题确认、生成文章、生成图片和文章排版完成公众号图文创作。
- 用户完成内容创作任一步骤后，系统能自动保存草稿，并能从草稿箱恢复到对应步骤继续创作。
- 用户在文章排版页能选择一个已授权微信公众号账号，并分别使用“同步到平台草稿箱”和“一键发布”。
- 用户在任务中心创建单次或重复微信公众号任务，到点后系统自动生成内容并按配置的发布动作执行。
- 平台要求扫码确认时，内容创作、草稿箱和任务中心均展示待人工确认，并可在确认后继续原发布作业。
- 系统只有在取得平台侧本次操作成功凭据后，才把任务或发布记录标记为成功。
- 多个任务可并行执行，状态分别展示为待执行、执行中、待人工确认、已生成平台草稿、已发布或失败。
- 发布失败时，任务详情展示失败原因并支持重试。
- 首页能展示账号、任务、内容的基础运营概览和快捷入口。
- 管理员能在系统设置中维护平台授权、成员 / 运营人、AI 配置和发布安全配置。
- 系统设置不出现复杂权限体系和平台接口技术参数配置。
- 数据回流后，AI 自动更新账号偏好规则，并保留版本记录与回滚入口。

## 11. 待确认问题

- 微信公众号真实页面结构变化后的适配和人工接管机制如何持续维护。
- 小红书、视频号后续是否能开放发布和数据接口。
- AI 自动改写规则的具体字段范围。
- 任务失败后的重试次数和提醒方式。
- 是否需要在内容发布前增加可选人工确认。
- 是否需要在首页增加跨账号运营概览看板。
