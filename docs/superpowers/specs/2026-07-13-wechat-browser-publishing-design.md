# 微信公众号浏览器真实发布设计

## 目标

将内容创作、草稿箱和任务中心统一接入微信公众号真实发布能力。发布器直接复用用户在“账号矩阵”扫码登录后保存的浏览器登录态，不要求用户提供公众号 AppID 或 AppSecret。

系统提供两个彼此独立的动作：

- **同步到平台草稿箱**：把内容真实保存到所选公众号后台的草稿箱，不公开发布。
- **一键发布**：把内容真实发布到所选公众号，并在平台侧验证发布结果。

成功的定义是公众号后台确实出现对应草稿或已发布作品。只生成本地发布包、只完成页面填写或只点击按钮均不算成功。

## 本轮范围

本轮真实发布范围只包含微信公众号：

- 内容项目固定为微信公众号内容，一次操作只选择一个已授权公众号账号。
- 不支持同一篇内容同时发布到多个平台。
- 小红书和抖音继续保留真实账号登录与数据同步，待各自内容创作模块开发后再接入发布。
- 视频号本轮只保留账号与数据能力，待视频创作模块完成后再实现发布。

## 总体架构

新增统一的 `PublishCoordinator`。内容创作、草稿箱和定时任务只提交标准化发布请求，不直接操作平台页面。

核心组件：

1. **AccountSessionResolver**
   - 根据 `account_id` 读取账号矩阵保存的浏览器 Profile。
   - 启动发布前检查登录是否有效。
   - 核验浏览器当前登录的公众号与用户选择的账号一致。

2. **WechatBrowserPublisher**
   - 使用账号独立的 Chrome Profile 打开 `mp.weixin.qq.com`。
   - 进入公众号图文编辑器，填写标题、摘要、作者、正文和排版。
   - 将本地封面图和正文配图真实上传到公众号素材系统。
   - 根据请求动作执行“保存草稿”或“发布”。

3. **WechatPublishVerifier**
   - 草稿模式：从保存接口响应或公众号草稿列表验证草稿存在。
   - 发布模式：从发布接口响应或公众号已发布列表验证作品存在。
   - 返回平台草稿或作品标识、链接、验证时间和脱敏证据。

4. **PublishJobStore**
   - 持久化执行阶段、平台结果、失败原因、重试次数和人工确认状态。
   - 为三个业务入口提供一致的进度和结果。

## 执行流程

### 同步到平台草稿箱

1. 用户选择已授权公众号账号并点击“同步到平台草稿箱”。
2. 后端创建操作类型为 `draft` 的发布任务。
3. 检查登录态和公众号身份。
4. 打开编辑器，上传封面和正文图片，写入完整内容。
5. 执行公众号后台的保存草稿动作。
6. 从平台响应或草稿列表验证结果。
7. 验证成功后状态变为“已同步平台草稿”；否则记录失败。

### 一键发布

1. 用户选择已授权公众号账号并点击“一键发布”。
2. 后端创建操作类型为 `publish` 的发布任务。
3. 复用相同的登录检查、素材上传和内容填写流程。
4. 先保存平台草稿，再执行公众号后台的发布动作。
5. 如果公众号后台要求管理员或运营者扫码确认，任务进入“待人工确认”，保留同一浏览器窗口和执行现场。
6. 用户完成平台安全确认后，任务自动继续。
7. 从公众号已发布列表或平台响应验证结果，验证成功后状态变为“已发布”。

管理员确认是公众号平台可能触发的安全校验，不是本系统额外增加的审批。没有触发校验时，发布器直接继续执行；系统不得绕过平台安全机制。

## 业务入口

### 内容创作

文章排版完成后展示：

- 已授权公众号账号选择器。
- “同步到平台草稿箱”按钮。
- “一键发布”按钮。
- 发布进度与结果抽屉。

### 草稿箱

完成排版的本地草稿进入详情后复用同一发布面板。系统本地草稿仍按现有逻辑自动保存，平台草稿是另一个独立状态。

### 任务中心

新建和编辑任务时增加“发布方式”：

- 一键发布，默认选项。
- 同步到平台草稿箱。

到期任务调用相同的 `PublishCoordinator`。如直接发布遇到公众号安全确认，任务进入“待人工确认”，不标记失败或成功。

## 后端接口

统一使用发布任务接口：

- `POST /api/publish-jobs`
  - 输入：内容项目、目标账号、来源入口、`draft` 或 `publish` 动作。
  - 输出：发布任务 ID 和初始状态。
- `GET /api/publish-jobs/{id}`
  - 返回执行阶段、平台结果、失败原因和人工确认状态。
- `POST /api/publish-jobs/{id}/retry`
  - 从可恢复阶段重新执行失败任务。
- `POST /api/publish-jobs/{id}/resume`
  - 管理员完成平台确认后继续验证和收尾。

原有发布包继续保存最终标题、排版正文和图片清单，但发布包本身不代表平台发布成功。

## 数据与状态

发布任务至少记录：

- 内容项目 ID 和发布包 ID。
- 来源入口：内容创作、草稿箱或任务中心。
- 目标账号 ID 和执行时的账号名称快照。
- 操作类型：`draft` 或 `publish`。
- 当前执行阶段、重试次数和更新时间。
- 平台草稿 ID、作品 ID、平台链接和验证时间。
- 失败阶段、失败原因和脱敏验证证据。

状态流转：

`等待执行 -> 检查登录 -> 上传素材 -> 填写内容 -> 已同步平台草稿`

或：

`等待执行 -> 检查登录 -> 上传素材 -> 填写内容 -> 发布中 -> 待人工确认 -> 已发布`

任一阶段失败均进入“失败”，不得转换为模拟成功。

## 异常与恢复

系统需要明确区分：

- 登录失效：提示重新扫码登录后重试。
- 登录账号不匹配：阻止发布，避免发错账号。
- 图片或素材上传失败：保留已完成步骤并允许重试。
- 公众号编辑器结构变化：记录失败阶段、当前页面和脱敏页面信息。
- 等待管理员确认：暂停任务并提供“继续执行”。
- 平台结果验证超时：保持失败或待确认，不得仅凭点击成功判定已发布。

人工接管必须打开同一账号的浏览器 Profile，避免重新登录或丢失当前编辑内容。

## 安全边界

- 浏览器登录态按账号隔离保存在本机，不返回前端，不写入普通日志。
- 不要求用户提供公众号 AppID、AppSecret 或访问令牌。
- 日志和发布证据必须脱敏，不保存完整 Cookie、二维码或授权凭据。
- 真实公开发布属于外部写入。首次联调使用明确标注的测试内容，并在执行前由用户确认目标账号和内容。

## 验收标准

1. 账号矩阵扫码登录后，无需再次登录即可完成公众号发布预检。
2. 内容创作和草稿详情都能选择最新授权的真实公众号账号。
3. 点击“同步到平台草稿箱”后，公众号草稿列表中能找到标题、正文、封面和正文配图。
4. 点击“一键发布”后，公众号已发布列表中能找到作品；如触发安全确认，完成扫码后可继续并验证成功。
5. 定时任务按配置执行草稿同步或直接发布，并保存真实平台结果。
6. 三个业务入口使用相同状态和错误结构。
7. 登录失效、账号不匹配、上传失败和页面变化均不会产生虚假成功记录。
8. 自动测试覆盖状态流转、入口路由、失败恢复和结果验证；真实账号联调分别验证平台草稿与直接发布。
